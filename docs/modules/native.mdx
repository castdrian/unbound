### What is the native bridge?

Some capabilities live in React Native modules rather than JavaScript. The `native` API resolves those modules and exposes the handles Unbound uses most often.

The loader also installs two JSI globals:

- `UnboundNative` is the versioned generic native plugin bridge.
- `UnboundPlatform` contains platform-wide helpers that are not plugin-specific.

Feature-specific native implementations do not belong in either global. Plugins use the generic bridge to implement their own behavior in JavaScript.

### Resolving native modules

A native module's name varies across Discord versions. `getNativeModule` checks each candidate in order against both `NativeModules` and the TurboModule registry.

```ts
import { native } from '@unbound-app/api';

const FileManager = native.getNativeModule(
	'NativeFileModule',
	'DCDFileManager',
	'RTNFileManager',
);
```

### Built-in handles

`BundleInfo`, `BundleManager`, `DeviceInfo`, and the file manager are resolved for you. Prefer `fs` for file operations because it handles paths and encodings.

### Reloading

`reload()` persists pending settings before asking the bundle manager to reload.

```ts
import { native } from '@unbound-app/api';

await native.reload();
```

### Platform helpers

`NativePlatform` is optional because it is only present inside a running Unbound loader environment. It exposes device information, app provenance, and Hermes bytecode evaluation.

```ts
import { native } from '@unbound-app/api';

const model = native.NativePlatform?.device.getModel();
const source = native.NativePlatform?.app.getSource();
```

`NativePlatform.evaluateBytecode` accepts a Hermes `ArrayBuffer` and evaluates it in the current runtime. It throws when the argument is not valid Hermes bytecode or when evaluation fails.

### Generic plugin bridge

`NativePlugin` is the public JavaScript view of the native ABI. The loader publishes it as `globalThis.UnboundNative`; the client scopes it to each plugin according to the manifest capabilities.

```ts
import { native } from '@unbound-app/api';

export default {
	start(context) {
		const bridge = context?.native;
		if (!bridge) return;

		const messageClass = bridge.objc.getClass('DCDMessage');
		if (!messageClass) return;
		const message = bridge.objc.alloc(messageClass);
		bridge.objc.call(message, 'content');
	},
};
```

The bridge exposes these version and capability fields:

<ParamField path='apiVersion' type='string'>
	The version of the JavaScript API consumed by plugins.
</ParamField>
<ParamField path='abiVersion' type='string'>
	The version of the native ABI implemented by the loader.
</ParamField>
<ParamField path='capabilities' type='string[]'>
	The native capabilities available in this loader build.
</ParamField>

### Objective-C operations

The `objc` namespace supports class lookup, allocation, selector calls, superclass calls, ivar access, associated objects, registered structs, arrays, data conversion, and generic hooks.

```ts
const { native } = pluginContext;
const cell = native.objc.getClass('DCDMessageTableViewCell');

const token = native.objc.hook(cellName, 'prepareForReuse', {
	before(context) {
		const viewModel = native.objc.getIvar(context.self, '_viewModel');
		if (viewModel) native.objc.call(viewModel, 'description');
	},
});

```

Hook arguments are borrowed until the callback returns. Retain values explicitly when they need to outlive the callback. `original()` is synchronous only when the callback runs on the hook thread; cross-thread calls fail closed to avoid deadlocks. Disposing a plugin context removes its hooks, associations, and bridge resources, and all later calls through that context are rejected.

`call` runs on the current runtime thread. `invoke` accepts an explicit thread policy such as `current` or `main`; unsupported synchronous crossings fail with a structured error.

### Raw FFI operations

The `ffi` namespace resolves symbols from already-loaded images and invokes non-variadic signatures made from supported scalar, pointer, Objective-C, and registered struct types.

```ts
const symbol = native.ffi.symbol('SomeLoadedSymbol');
if (symbol) {
	const value = native.ffi.call(symbol, {
		returnType: 'i32',
		args: ['pointer'],
	}, pointer);
}
```

The v1 bridge does not expose arbitrary memory access, `dlopen`, variadic calls, unknown structs, vectors, unions, bitfields, or plugin-supplied native closures.

### Capabilities and lifecycle

Declare only the capabilities a plugin needs in its manifest:

- `native.objc.classes`
- `native.objc.invoke`
- `native.objc.ivars`
- `native.objc.associations`
- `native.objc.hooks`
- `native.ffi.symbols`
- `native.ffi.call`

The addon manager validates capability names and the optional minimum API version before calling `start(context)`. `context.native` is scoped to the plugin. `context.dispose()` is called during stop, unload, reload, and failed startup cleanup.

Existing plugins can continue to accept a context-less `start` function, but new plugins should use the scoped context so native resources cannot escape their lifecycle.
